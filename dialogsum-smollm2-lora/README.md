# DialogSum: суммаризация диалогов с помощью SmolLM2 и LoRA

## О проекте

В этом проекте я исследовал задачу автоматической суммаризации диалогов
на датасете **DialogSum**.

Основная цель — проверить, насколько хорошо небольшая instruction-модель
**SmolLM2-360M-Instruct** справляется с суммаризацией без
дополнительного обучения и насколько сильно можно улучшить её качество с
помощью **LoRA fine-tuning**.

Эксперимент построен как последовательное сравнение:

``` text
Подготовка данных
        ↓
EDA
        ↓
Non-ML baseline
        ↓
Zero-shot SmolLM2
        ↓
BLEU / ROUGE
        ↓
LoRA fine-tuning
        ↓
Inference обученной модели
        ↓
BLEU / ROUGE
        ↓
LLM-as-a-judge
        ↓
Анализ результатов
```

------------------------------------------------------------------------

## Датасет

Использовался датасет **DialogSum**, содержащий диалоги и краткие
summaries этих диалогов.

В качестве входных данных использовалось поле `dialogue`, а целевым
результатом являлось `summary`.

В обучающей выборке было **12 460 примеров**.

Перед обучением были выполнены базовые проверки данных:

- размеры train / validation / test;
- наличие пропусков;
- наличие дубликатов;
- структура данных;
- длины диалогов и summaries;
- проверка корректности train / validation / test.

------------------------------------------------------------------------

# 1. Non-ML baseline

В качестве простого baseline использовалась эвристика без машинного
обучения.

Идея baseline — сформировать summary из частей исходного диалога. Это
позволяет получить отправную точку и понять, насколько полноценная
модель улучшает результат относительно простого подхода.

### Результаты

| Метрика    | Non-ML |
|------------|-------:|
| BLEU       | 0.0619 |
| ROUGE-1    | 0.1978 |
| ROUGE-2    | 0.0695 |
| ROUGE-L    | 0.1736 |
| ROUGE-Lsum | 0.1738 |

------------------------------------------------------------------------

# 2. Zero-shot SmolLM2

В качестве основной модели использовалась **SmolLM2-360M-Instruct**.

Сначала модель была проверена без дополнительного обучения. Модель
получила исходный диалог и prompt с просьбой сформировать краткое
summary.

Inference выполнялся с использованием **vLLM**.

### Результаты Zero-shot

| Метрика    | Zero-shot |
|------------|----------:|
| BLEU       |    0.0892 |
| ROUGE-1    |    0.3130 |
| ROUGE-2    |    0.1026 |
| ROUGE-L    |    0.2444 |
| ROUGE-Lsum |    0.2646 |

Уже на этом этапе модель показала улучшение относительно простого
baseline.

------------------------------------------------------------------------

# 3. LoRA fine-tuning

После проверки zero-shot качества модель была дообучена на DialogSum с
использованием **LoRA**.

Главное преимущество LoRA заключается в том, что не требуется обновлять
все параметры базовой модели.

В нашем эксперименте:

| Параметр                  |    Значение |
|---------------------------|------------:|
| Всего параметров          | 370 505 600 |
| Обучаемых параметров      |   8 683 520 |
| Доля обучаемых параметров |       2.34% |

Во время обучения изменялась только небольшая часть параметров модели, а
основные веса базовой модели оставались замороженными.

### LoRA configuration

``` text
r = 16
lora_alpha = 16
lora_dropout = 0
bias = none
```

LoRA применялась к следующим модулям:

``` text
q_proj
k_proj
v_proj
o_proj
gate_proj
up_proj
down_proj
```

## Параметры обучения

``` text
Epochs:                       1
Batch size per device:       2
Gradient accumulation:       4
Effective batch size:        8

Learning rate:               2e-4
Warmup steps:                50
Weight decay:                0.01
LR scheduler:                linear

Precision:                   BF16
Max sequence length:         2048
Packing:                     False
```

Для обучения использовались **Unsloth** и **TRL SFTTrainer**.

------------------------------------------------------------------------

# 4. Результаты LoRA

После завершения fine-tuning обученная модель была использована для
генерации summaries на тестовой выборке.

| Метрика    | Zero-shot |       LoRA |
|------------|----------:|-----------:|
| BLEU       |    0.0892 | **0.2969** |
| ROUGE-1    |    0.3130 | **0.4889** |
| ROUGE-2    |    0.1026 | **0.2348** |
| ROUGE-L    |    0.2444 | **0.4062** |
| ROUGE-Lsum |    0.2646 | **0.4067** |

После LoRA наблюдается рост по всем использованным метрикам.

Например:

``` text
BLEU:
0.0892 → 0.2969

ROUGE-L:
0.2444 → 0.4062
```

Это показывает, что даже относительно небольшую модель можно заметно
адаптировать под конкретную задачу с помощью parameter-efficient
fine-tuning.

------------------------------------------------------------------------

# 5. LLM-as-a-judge

BLEU и ROUGE позволяют оценить сходство с эталонными summaries, но они
не полностью отражают качество текста.

Например, summary может иметь хорошее совпадение по словам с reference,
но при этом содержать факты, которых не было в исходном диалоге.

Поэтому дополнительно была проведена оценка с помощью
**LLM-as-a-judge**.

В качестве judge использовалась:

``` text
Qwen/Qwen3-8B
```

через Hugging Face Inference Providers.

Для каждого примера judge получал:

- исходный dialogue;
- reference summaries;
- summary от zero-shot модели;
- summary от LoRA-модели.

Оценка проводилась по шкале от 1 до 5 по четырём критериям.

### Factuality

Насколько summary соответствует исходному диалогу и не содержит
выдуманных фактов.

### Coverage

Насколько хорошо summary сохраняет основные события и информацию
диалога.

### Conciseness

Насколько summary краткое и не содержит лишней информации.

### Overall

Общая оценка качества summary.

Из-за ограничения бесплатного inference было оценено **10 тестовых
примеров**.

## Результаты LLM-as-a-judge

| Критерий    | Zero-shot |    LoRA |
|-------------|----------:|--------:|
| Factuality  |       1.2 | **2.6** |
| Coverage    |       1.2 | **2.7** |
| Conciseness |       1.3 | **3.1** |
| Overall     |       1.2 | **2.6** |

Из 10 оценённых примеров:

``` text
LoRA лучше:       7
Zero-shot лучше:  1
Ничья:            2
```

Таким образом, LoRA получила более высокую `overall` оценку в 7 из 10
рассмотренных случаев.

Важно отметить, что LLM-as-a-judge был проведён только на 10 примерах.
Поэтому эти результаты являются дополнительной качественной проверкой и
не должны рассматриваться как статистически устойчивая оценка всей
тестовой выборки.

------------------------------------------------------------------------

# 6. Что изменилось после обучения

До обучения модель уже могла выполнять задачу суммаризации, однако
качество было относительно низким.

После LoRA:

- summaries стали ближе к эталонным;
- модель лучше выделяла основную информацию диалога;
- summaries стали более компактными;
- выросло лексическое совпадение с reference;
- выросли BLEU и ROUGE;
- LLM-as-a-judge также дал более высокие оценки LoRA по всем четырём
  критериям.

При этом дообучение не сделало модель полностью безошибочной.

В отдельных примерах всё ещё встречаются:

- пропущенная информация;
- неточные формулировки;
- отдельные фактические ошибки;
- добавление информации, которой не было в исходном диалоге.

Поэтому рост метрик не означает, что модель стала идеальной.

# 7. Итоговое сравнение

| Модель    |       BLEU |    ROUGE-1 |    ROUGE-2 |    ROUGE-L |
|-----------|-----------:|-----------:|-----------:|-----------:|
| Non-ML    |     0.0619 |     0.1978 |     0.0695 |     0.1736 |
| Zero-shot |     0.0892 |     0.3130 |     0.1026 |     0.2444 |
| **LoRA**  | **0.2969** | **0.4889** | **0.2348** | **0.4062** |

По результатам эксперимента LoRA показала заметно более высокие
результаты по сравнению с zero-shot моделью.

Наиболее заметный рост наблюдается по BLEU и ROUGE-метрикам:

``` text
BLEU       0.0892 → 0.2969
ROUGE-1    0.3130 → 0.4889
ROUGE-2    0.1026 → 0.2348
ROUGE-L    0.2444 → 0.4062
```

# 8. Финальный вывод

В рамках проекта был построен полный pipeline для адаптации небольшой
LLM под задачу суммаризации диалогов.

Сначала была проверена простая эвристика, затем исходная SmolLM2 в
zero-shot режиме. После этого модель была дообучена на DialogSum с
помощью LoRA.

При этом обучалось только около **2.34% параметров модели**, что
позволило значительно изменить поведение модели под задачу без полного
fine-tuning.

После обучения качество заметно выросло по всем использованным BLEU и
ROUGE метрикам.

Дополнительная оценка с помощью LLM-as-a-judge на 10 примерах также
показала преимущество LoRA: более высокая `overall` оценка была получена
в 7 из 10 случаев.

При этом результаты LLM-as-a-judge нельзя считать полноценной
статистической оценкой, поскольку была использована небольшая выборка из
10 примеров.

Главный результат эксперимента заключается в том, что **LoRA позволила
существенно адаптировать небольшую SmolLM2-360M-Instruct под конкретную
задачу суммаризации при обучении лишь небольшой части её параметров**.

Проект также показывает полный практический цикл работы с LLM:

``` text
Подготовка данных
        ↓
EDA
        ↓
Baseline
        ↓
Zero-shot inference
        ↓
Оценка качества
        ↓
LoRA fine-tuning
        ↓
Inference обученной модели
        ↓
BLEU / ROUGE
        ↓
LLM-as-a-judge
        ↓
Сравнение и анализ результатов
```

------------------------------------------------------------------------

## Ограничения эксперимента

Основные ограничения:

1.  LoRA обучалась только **1 эпоху**.
2.  LLM-as-a-judge был проведён только на **10 примерах**.
3.  BLEU и ROUGE не полностью отражают фактическую корректность summary.
4.  Даже после fine-tuning отдельные summaries содержат ошибки.
5.  Не проводился полноценный подбор гиперпараметров через серию
    экспериментов.
6.  Результаты LLM-as-a-judge зависят от выбранной judge-модели и
    формулировки prompt.

Поэтому полученные результаты показывают эффективность выбранного
подхода в рамках данного эксперимента, но не являются доказательством
того, что найденная конфигурация является оптимальной.

## Как запустить

Установить необходимые библиотеки:

``` bash
pip install torch
pip install transformers
pip install datasets
pip install trl
pip install peft
pip install unsloth
pip install vllm
pip install evaluate
```

После этого открыть notebook и последовательно выполнить ячейки:

``` text
1. Загрузка и подготовка данных
2. EDA
3. Baseline
4. Zero-shot inference
5. Оценка BLEU / ROUGE
6. LoRA fine-tuning
7. Сохранение LoRA adapter
8. Inference обученной модели
9. Повторная оценка
10. LLM-as-a-judge
11. Финальное сравнение
```

Для LLM-as-a-judge требуется API-токен Hugging Face. Токен следует
передавать через переменную окружения или `getpass` и **не сохранять
непосредственно в notebook или GitHub**.
